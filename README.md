# GenomeHacker
## 作品概要
この作品は、敵の行動を行動が組まれているノードを組み合わせる事で作成することができるツールです。
元々は「敵の行動を組み換えプレイヤー側がシナジーを作ることができるゲーム」として作成していましたが、
上手いことゲーム性をもたせられなかったため、それならいっそのことツールとして作成してしまおうということで最終的に
ゲームとしての完成度を上げるのではなく、ツールとしての完成度を上げる事に尽力しました。
元がゲームとして作成したものなため、変更した挙動はすぐに反映され確認することができるようになっています。

## この作品の売りポイント
### 処理の最適化
制作にあたり、処理の高速化をするための工夫を取り入れています。一番効果があったものはデータの管理方法(メモリ上のデータ管理)を工夫したことです。
今まで制作で使用していたデータの管理方法(ポインタ管理)の場合、実際のデータはランダムな場所に配置されておりデータを見に行くために都度データの場所を
確認してからデータを取りに行くような形になっていたため無駄が発生していました。
この作品のデータの管理方法(実体管理)では、データが必ず連続して配置されるようなコードの組み方をしており先頭のデータを見れば次のデータは1つ右の位置にある、
そのため最初の場所がわかれば後はデータの位置を気にしなくて良い!という仕組みにしています。
データの管理においても、ポインタ管理ではなくなったことにより仮想関数分のコストを考慮せず実行できるようになったため、
これらの工夫により導入前後比で20%の処理の高速化に成功しています。
### 使いやすいツールを目指したこと
この作品が完成したタイミングでは各ノードの値はプログラム内で固定の値を使用していたため、後から柔軟に変更することが出来ませんでした。
作品を評価してもらえる機会があり、この作品を触っていただいた方から「値を後から変更できるとより使い勝手が向上すると思う」との意見を頂戴し、
「プログラマー以外がこのツールを使用したとしても問題なく使用できる事」を目指しました。
既存のノードを動かす動作がクリックで掴んで動かし再度クリックで位置の確定、という動作で値を変更する仕組みを取り入れた場合操作が競合してしまうことから
ノードを動かす動作はドラック中に行うようにし、クリックした時にノードに設定されている"移動量"や"発射間隔"などの値を変更できるウィンドウを表示する仕様設計にしました。
ノードをホバーすると説明文を表示、という機能も搭載しているためこのノードがどういう動きをするかがわからないという事態も軽減するようにしています。

## 作成にあたり苦労した点
敵の行動を変更する箇所であるノードを組み替える画面の作成に苦労しました。GUIを用いているため、見た目の位置を入れ替える処理や、
戻るボタンを押した時にノードの並び位置が確定し実際のデータに反映する、という処理の作成に時間を掛けています。
また、元々ゲームを目指して作成していた関係上ボタンの挙動やテキストの描画などの汎用的な処理を楽に管理できるようにコードの作成を行っています。
この部分にも時間を掛けており、その結果描画するために必要なパラメーターを入力するだけでそれらを配置できるような設計にしています。
